# SillyTavern Cloud Backup

把 SillyTavern 的角色卡、聊天记录、用户人设、预设、美化、世界书、API 配置备份到 WebDAV 网盘。前端扩展 + 一个很小的服务端插件，避开浏览器直连 WebDAV 的跨域限制。

装好之后在酒馆的「扩展」页面里显示为**酒馆云备份**。

WebDAV 地址由用户手动填写，不内置任何服务商的固定地址。

## 它能做什么

- **精确到单张角色卡的范围选择**：只备份你在意的那几张卡。
- **聊天记录精确到单条**：角色卡在范围菜单里是文件夹，展开就能勾这个角色名下的某几条聊天；也可以一键把所选角色的聊天全带上。
- **云端按角色名存放**：本地 png 文件名是一串乱码的卡，在网盘里也按角色名显示，一眼能认出来。
- **世界书只列独立的**：已经内嵌在角色卡里的世界书不会重复出现，跟着角色卡一起备份。开了 `lazyLoadCharacters` 也判得准。
- **预设与美化按文件勾选**：OpenAI 预设、快速回复、UI 主题都能勾到具体某一个；背景图只备份你自己上传的，酒馆自带的那批风景图不会传。
- **用户人设**：人设名、描述、注入设置连同头像一起备份，逐个勾选。网盘上一个人设一个文件夹，下载时只动你勾的那个，你自己的其他人设不会被删掉也不会被带出来。
- **API 配置**：连接配置档逐个勾选，网盘上一档一个文件（以配置名命名），可以连它引用的 API 密钥与代理密码一起带上，换台机器不用重新填一遍。
- **下载完直接可用**：角色卡、世界书、预设、主题、背景图、用户人设都会自动刷进酒馆，不用重载页面。
- **上传与下载两个动作**，各自的影响范围写在按钮上，动手前可以先预览。
- **云端文件管理**：在面板里浏览网盘上的备份，可搜索、可按时间排序、可一键筛出当前角色，能指定下载某一个文件，也能删除。
- **跳过没变的文件**：按内容哈希比对，重复上传不消耗流量。
- 自动上传，支持按时间间隔和聊天变化触发。
- 支持坚果云、InfiniCLOUD，以及兼容标准 WebDAV 的服务。

## 安装

这个扩展包含两部分：前端扩展和服务端插件。**两部分都要装**，且**装完必须重启 SillyTavern** —— 服务端插件只在酒馆启动时加载一次，不重启面板上就会显示「后端未加载」。

仓库地址：[https://github.com/ZZZa-o/sillytavern-cloud-backup](https://github.com/ZZZa-o/sillytavern-cloud-backup)

### 方式一：一键安装（推荐）

#### 安卓用户（Termux）

1. 先装好 git 和 curl：

   ```bash
   pkg install git curl
   ```

2. 再运行安装脚本：

   ```bash
   bash <(curl -sL https://cdn.jsdelivr.net/gh/ZZZa-o/sillytavern-cloud-backup@main/install.sh)
   ```

#### Linux / macOS 用户

只需要运行一条命令：

```bash
bash <(curl -sL https://cdn.jsdelivr.net/gh/ZZZa-o/sillytavern-cloud-backup@main/install.sh)
```

提示找不到 git 的话，先按系统装一下：Debian/Ubuntu 用 `sudo apt install git`，macOS 用 `brew install git`。

#### Windows 用户

Windows 没有自带 bash。装了 Git for Windows 之后，在酒馆目录里右键选「Git Bash Here」，然后运行上面那条同样的命令。不想装 Git Bash 就用下面的方式二或方式三。

#### 通用说明

- 上面用的是 jsDelivr 链接，国内访问通常更稳。也可以换成原始链接：

  ```bash
  bash <(curl -sL https://raw.githubusercontent.com/ZZZa-o/sillytavern-cloud-backup/main/install.sh)
  ```

- 必须用 `bash` 执行，不能用 `sh`。
- 脚本会自动找到 SillyTavern 目录。找不到时把路径作为参数传进去：

  ```bash
  bash install.sh ~/SillyTavern
  ```

- 脚本做三件事：安装前端扩展、安装服务端插件、把 `config.yaml` 里的 `enableServerPlugins` 设为 `true`（改动前会备份原文件）。装完重启酒馆即可。
- **以后再次运行同一条命令就是更新。**
- 如果之前是手动复制安装的，脚本会把旧目录移到 `_sillytavern-cloud-backup-old/` 再重新安装。旧目录必须挪出 `plugins/`，否则酒馆会把它当成第二个插件加载并报 id 冲突。

### 方式二：两条 git 命令

```bash
cd ~/SillyTavern
git clone https://github.com/ZZZa-o/sillytavern-cloud-backup.git plugins/sillytavern-cloud-backup
git clone https://github.com/ZZZa-o/sillytavern-cloud-backup.git public/scripts/extensions/third-party/sillytavern-cloud-backup
```

然后在 `config.yaml` 里设置 `enableServerPlugins: true` 并重启。

服务端插件可以直接 clone 整个仓库，是因为仓库根的 `package.json` 里 `main` 指向 `server/index.js`，SillyTavern 的插件加载器会优先按它解析入口。

### 方式三：手动复制

1. 把本项目整个文件夹复制到：

   ```text
   SillyTavern/public/scripts/extensions/third-party/sillytavern-cloud-backup
   ```

2. 再把 `server/` 目录和 `package.json` 一起复制到：

   ```text
   SillyTavern/plugins/sillytavern-cloud-backup/
   ```

   复制后应该是 `plugins/sillytavern-cloud-backup/package.json` 和 `plugins/sillytavern-cloud-backup/server/index.js`。
   `package.json` 不能漏，插件加载器靠它里面的 `main` 找到入口。

3. 打开 SillyTavern 的 `config.yaml`，确认服务端插件已启用：

   ```yaml
   enableServerPlugins: true
   ```

4. 重启 SillyTavern。

5. 进入 SillyTavern 的「扩展」页面，展开「酒馆云备份」。

### 关于自动更新

用方式一或方式二安装时，插件目录本身就是一个 git 仓库。SillyTavern 的 `enableServerPluginsAutoUpdate` 默认为 `true`，会在每次启动时自动拉取服务端插件的更新。不想要这个行为就在 `config.yaml` 里关掉它。

手动复制安装（方式三）不具备自动更新能力。

## Docker / NAS / VPS 安装

Docker 部署的酒馆有一个绕不过去的前提：**服务端插件必须落在容器的 `/home/node/app/plugins` 里**。官方镜像把这个目录设计成挂载卷，但不少教程只映射了 `config` 和 `data`，没映射 `plugins`。这种情况下无论怎么装，酒馆启动时都读不到插件，面板上就一直显示「后端未加载」。

前端扩展没有这个问题 —— 直接在酒馆的「扩展」页面用 GitHub 链接安装就行，它落在 `data/<用户>/extensions/` 里，而 `data` 必然是映射出来的。

### 先确认容器映射了哪些目录

在 NAS 或 VPS 的终端里：

```bash
docker ps --format '{{.Names}}\t{{.Image}}'
docker inspect <容器名> --format '{{range .Mounts}}{{.Source}} -> {{.Destination}}{{println}}{{end}}'
```

第二条命令的输出里找有没有这一行：

```text
/宿主机/某个路径  ->  /home/node/app/plugins
```

**有** —— 记下箭头左边的宿主机路径，跳到下一节。
**没有** —— 先补上这条映射：停止容器 → 编辑容器 → 存储空间/卷 里添加一条，宿主机随便挑个目录（建议就放在酒馆数据目录旁边，如 `/volume1/docker/sillytavern/plugins`），容器内路径填 `/home/node/app/plugins` → 保存并启动。群晖的 Container Manager、威联通的 Container Station 都在图形界面上做这一步。

### 安装

在宿主机上，对着那个**装着 `config/` 和 `data/` 的目录**运行安装脚本，它会自动认出这是 Docker 挂载目录：

```bash
bash <(curl -sL https://cdn.jsdelivr.net/gh/ZZZa-o/sillytavern-cloud-backup@main/install.sh) /volume1/docker/sillytavern
```

脚本结束时会把三个实际写入路径打印出来，照着核对一遍。然后**重启容器**。

没装 git 的 NAS 可以手动来：把仓库下载解压成 `<宿主机plugins目录>/sillytavern-cloud-backup/`（里面要能看到 `package.json` 和 `server/index.js`），再编辑 `config/config.yaml` 加上 `enableServerPlugins: true`，重启容器。

### 为什么之前在容器里跑脚本会"装成功但没效果"

容器内的 `/home/node/app/config.yaml` 是一个指向 `config/config.yaml` 的**符号链接**。旧版脚本用 `sed -i` 改它，而 `sed -i` 的做法是"写临时文件再改名顶替"，结果符号链接本身被替换成了普通文件 —— 改动落在容器内部的临时层里，映射出来的 `config/config.yaml` 一个字都没变。容器一重启，`enableServerPlugins` 又回到 `false`。

现在的脚本会先把符号链接解引用到真身再改，并且用重定向写入而不是改名，链接结构原样保留。

### VPS

VPS 上如果是 `git clone` 装的酒馆（不是 Docker），直接在酒馆目录里跑一键安装命令即可，和 Linux 桌面没有区别：

```bash
cd ~/SillyTavern
bash <(curl -sL https://cdn.jsdelivr.net/gh/ZZZa-o/sillytavern-cloud-backup@main/install.sh)
```

VPS 上跑 Docker 的话，步骤和上面 NAS 完全一样。

## 首次使用

1. 确认面板左上角显示「后端已连接」。显示「后端未加载」就是没重启酒馆，或服务端插件没装对。
2. 填写 **WebDAV 地址**、**用户名**、**远端目录**（默认 `sillytavern-backup`）、**授权密码**。
3. 点 **保存配置**。四项一起存，没有单独的"保存密码"按钮。
4. 点 **测试连接**。它会往远端目录传一个测试文件再删掉，能通过说明读写都没问题。
5. 点 **范围** 挑要备份的内容（见下节）。
6. 点 **上传到云端**。

密码保存成功后，密码框会永远显示为空，占位符变成「已保存，留空则不修改」。这是刻意的：密码只进不出，后端不会把明文回传给页面。想换密码就填新的再点保存配置。

## 备份范围怎么选

点面板上的 **范围** 按钮，弹窗里是六个按钮：

| 按钮 | 点击行为 |
| --- | --- |
| **角色卡** | 进入二级菜单。每张卡是一个文件夹，勾文件夹标题选中这张卡，展开它就能勾具体某几条聊天记录 |
| **用户人设** | 进入二级菜单，逐个勾选人设 |
| **预设** | 进入二级菜单，按目录展开勾具体的预设文件 |
| **美化** | 进入二级菜单，按目录展开勾具体的主题；背景图是整类开关 |
| **世界书** | 进入二级菜单，勾选具体的世界书 |
| **API 配置** | 进入二级菜单，逐个勾选连接配置档 |

**已选中的按钮外边框会加粗高亮**，按钮上还标着数量（如「角色卡（3 + 聊天）」「世界书（全部 5）」）。按钮下方有一行备注，写着当前完整的范围。

### 角色卡与聊天记录

聊天记录长在角色卡菜单里，因为它本来就跟着角色走：

```
[全选] [取消全选] [仅当前角色] [含聊天记录]
┌────────────────────────────────────────┐
│ ▸ ☑ 角色甲              3 条聊天 · 240 KB │
│ ▾ ☑ 角色乙              5 条聊天 · 1.2 MB │
│      ☑ 2026-08-01 12h30m         88 KB │
│      ☐ 2026-07-28 09h15m         42 KB │
│      …                                 │
└────────────────────────────────────────┘
已选 2 / 12 张卡，聊天记录 全部（排除 1 条）
```

- **文件夹标题上的复选框** = 这张角色卡本身
- **展开后的条目** = 这个角色的聊天记录，逐条勾。文件夹默认收起，聊天明细在展开那一刻才向后端要
- **「含聊天记录」** 一键把所选角色的聊天全带上，按钮颜色加深表示当前带着聊天。带上之后仍可展开某张卡，单独取消掉其中几条
- **群聊与群组** 跟着「含聊天记录」走：它一键全带时群聊一并带上
- **全选 / 取消全选** 只作用于角色卡本身。大部分卡还没展开，它们的聊天明细不在页面上，聊天交给「含聊天记录」统一管
- 没勾角色卡，它名下的聊天一条都不会传

聊天文件按修改时间排列，最近聊的在最上面。

### 用户人设

人设在酒馆里没有自己的文件 —— 名字、描述、注入设置都存在 `settings.json` 里，`User Avatars/` 目录里只有头像图片。插件把这几个字段抽出来，**一个人设拼成一份 `persona.json`**，和它的头像一起放进网盘上以人设名命名的文件夹里：

```
用户人设/沈知微/persona.json      名字、描述、注入设置
用户人设/沈知微/1712345678901.png  头像
```

菜单里逐个勾选人设，只有勾中的那几个会被抽出来。默认人设本身也被勾中时，"哪个是默认"才一起带上。

一人一份是为了下载时互不牵连：在云端文件列表里勾一个人设，落地的就只有那一个人设，本机其他人设一个字都不会被动到（勾文件夹里的任意一项，同文件夹的另一项会自动跟上 —— 只拉头像不拉 `persona.json`，酒馆里会出现一个叫 `[Unnamed Persona]` 的空壳）。

从云端下载时是**合并**：同一个人设用云端版本覆盖，本机独有的人设留着不动，`settings.json` 里其余的内容一个字都不碰。下载完人设面板当场就变，不用刷新页面。

列表里列的是磁盘上真实存在的头像，和酒馆人设面板一致 —— `settings.json` 里残留的、头像早已删掉的旧条目不会出现。

### 预设与美化

预设与美化的二级菜单是文件夹形态：一个目录一块，标题上写着文件数与占用体积，点标题展开就能逐个勾。标题上的复选框是整目录开关。

| 预设 | 对应目录 | 勾选粒度 |
| --- | --- | --- |
| OpenAI 预设 | `OpenAI Settings/` | 逐个文件 |
| 快速回复 | `QuickReplies/` | 逐个文件 |

| 美化 | 对应目录 | 勾选粒度 |
| --- | --- | --- |
| UI 主题 | `themes/` | 逐个文件 |
| 背景图 | `backgrounds/` | 整类开关 |

背景图不列明细，整类一个开关。它只统计并备份**你自己上传的图**：酒馆首次创建用户目录时会把 `default/content/backgrounds/` 那二十来张自带风景图整份复制过来，插件按文件名认出它们并排除，标题旁边会写明排除了几张。换台机器装好酒馆，这些图本来就在。

### API 配置

菜单里列出连接管理器里的配置档，逐个勾选，每条后面标着「含密钥明文」或「无密钥」。

**勾中的配置档会连它引用的 API 密钥明文与代理密码一起备份**，换台机器不用重新填一遍。与人设同理，一档一份，网盘上按配置名命名（`API配置/我的Claude.json`），下载时只合并你勾的那一档。这些密钥是明文写在这些文件里的，介意就别勾这一类 —— 其余五类都不会读取密钥。没有被勾中的配置档引用到的密钥一个都不碰。

从云端下载时同样是合并：同一个配置档用云端版本覆盖，本机独有的留着。两样东西不跟着云端走 —— 「当前连着哪个配置档」和「哪个密钥正在用」都属于这台机器自己的状态，下载一份配置不会把你正在用的连接切走。

下载完**需要刷新页面**才生效。

二级菜单里有：

- **搜索框** —— 按角色名、世界书名或文件名过滤
- **全选** / **取消全选** —— 搜索状态下只作用于筛选出来的那些
- **仅当前角色**（只有角色卡菜单有）—— 一键只勾当前正在聊的那个角色
- **含聊天记录**（只有角色卡菜单有）—— 一键把所选角色的聊天全带上，开着时按钮颜色加深

把某一类（或某个目录）全部勾上时记录的是"全选"这个状态，所以**以后新导入的角色卡、新存的预设与主题会自动纳入备份**。想固定名单就手动勾选具体项。

几点需要知道的：

- **世界书列表只列独立世界书**。已经链接到某张角色卡、并且那张卡的 png 里内嵌了世界书数据（`character_book`）的，跟着角色卡一起备份，不在列表里重复出现。菜单底部会写明隐藏了几本。
  - 内嵌与否由服务端插件直接解析 png 判断，所以酒馆开着 `performance.lazyLoadCharacters` 也照样准。
  - 如果一本世界书被角色卡引用、但卡里没有内嵌副本（只是个引用），它会留在列表里并标上「卡内无副本，建议勾选」。勾上它，换台机器角色卡才能找到这本书。
- **全新安装时六类一律不勾**。备份什么由你决定 —— 装好后第一件事就是进「范围」勾一遍。

## 上传与下载

| 按钮 | 做什么 |
| --- | --- |
| **上传到云端** | 把范围内的本机文件推到网盘。内容相同的跳过。**云端多余的文件保留不动** |
| **从云端下载** | 把云端范围内的文件拉到本机，同名直接覆盖 |
| **预览变更** | 只比对不执行，列出两个方向各会动哪些文件 |

两端内容不同的文件会**同时出现在预览的上传清单和下载清单里** —— 点哪个按钮就以哪边为准。拿不准的时候先点预览，它不写入任何数据。

### 下载后要不要刷新页面

大部分情况不用。下载完成后插件会自动把新内容刷进酒馆，和你手动导入时的效果一样：

| 下载了什么 | 要不要刷新 | 走的什么入口 |
| --- | --- | --- |
| 角色卡 | 不用 | `getCharacters()`，顺带把列表排序切成「最近导入」 |
| 世界书 | 不用 | `updateWorldInfoList()` |
| 聊天记录 | 不用 | 「管理聊天文件」是现读的，落盘即可见 |
| OpenAI 预设 | 不用 | `getSettings()` 重拉一次，酒馆据此重建预设下拉框 |
| UI 主题 | 不用 | 同上 |
| 背景图 | 不用 | `getBackgrounds()` |
| 用户人设 | 不用 | 写回内存的 `power_user`，再调 `getUserAvatars()` 重绘人设面板 |
| 快速回复 | **要** | 列表由 QR 扩展自己读取，它没有留下重新加载的入口 |
| API 配置 | **要** | 连接管理器扩展没有导出任何重新加载的入口 |

## 云端文件管理

面板的「云端文件」区域直接列出网盘上的备份，按角色卡 / 聊天记录 / 用户人设 / 预设 / 美化 / 世界书 / API 配置分组折叠：

- **搜索框** —— 按路径过滤
- **当前角色** —— 一键把搜索框填成酒馆里正开着的角色名。云端按角色名存放，搜它就能把这个角色的卡和聊天一起筛出来
- **按路径 / 按时间** —— 切换排序。按时间是倒序，刚传上去的排在最前面
- **🔗 联动开关**（角色卡分组标题右端，默认开启）—— 开着时勾一张角色卡会连它名下的聊天记录一起勾上；关掉则只勾角色卡本身。开与关的图标和颜色不同
- 每行一个勾选框，分组标题上的勾选框可以整组全选
- **下载选中** —— 把勾选的文件拉回本机。能对应到酒馆数据目录的写回原位（同名覆盖）；对应不上的（元数据、手动传上去的杂项）落到 `backups/webdav-cloud-<时间戳>/`，不会污染数据目录
- **删除选中** —— 从网盘永久删除，不可撤销，会二次确认

插件自己的元数据目录 `.st-sync/` 也会显示出来，分组名是「插件元数据」。删它不会丢数据，只会让下次备份重新做一次全量比对，删除时会额外提示。

### 把某一条聊天同步到另一台设备

这里是精确到单个文件的入口，适合"在 A 设备聊完，想去 B 设备接着聊"：

**设备 A** 范围里勾上这个角色、开「含聊天记录」，点「上传到云端」。内容相同的会跳过，实际推上去的只有新产生的那条。

**设备 B**

1. 「云端文件」点 **刷新**
2. 点 **当前角色**（或手动搜角色名），再点 **按时间** 让最新的排到前面
3. 勾中那一条 `.jsonl`，点 **下载选中**

它会落回本机这个角色的聊天目录。两台设备上同一个角色的 png 文件名不同也没关系 —— 云端按角色名存放，落地时对回本机自己的 png。下载完重新打开一次「管理聊天文件」就能看到。

如果 B 设备上还没有这张角色卡，把 🔗 联动开关保持开启，直接勾中「角色卡」分组里那张卡，它的聊天会一并被选上。

## 云端目录结构

```text
<远端目录>/                        默认 sillytavern-backup
├─ 角色卡/
│  ├─ <角色名>.png                 按角色名存放
│  └─ <角色名>/                    角色卡的附件目录（如果有）
├─ 聊天记录/
│  ├─ <角色名>/
│  │  └─ <聊天文件>.jsonl
│  ├─ _群聊/<群名>/…
│  └─ _群组/<群组>.json
├─ 用户人设/
│  └─ <人设名>/                     一个人设一个文件夹
│     ├─ persona.json              人设名、描述与注入设置
│     └─ <头像文件>                 这个人设的头像
├─ 预设/
│  ├─ OpenAI Settings/<预设名>.json    第二层沿用酒馆的原目录名
│  └─ QuickReplies/<快速回复集>.json
├─ 美化/
│  ├─ themes/<主题名>.json
│  └─ backgrounds/<背景图>             只有你自己上传的，酒馆自带的不传
├─ 世界书/
│  └─ <世界书名>.json
├─ API配置/
│  └─ <配置名>.json                 一档一个文件，含它引用到的密钥明文
└─ .st-sync/
   ├─ index.json                  每个文件的哈希、来源设备、以及"云端文件名 ↔ 本地文件名"的对照
   └─ lock.json                   并发锁，避免两台设备同时上传互相踩踏
```

角色名里出现 `\ / : * ? " < > |` 这类文件系统非法字符时会被替换，并追加一段短哈希避免不同角色撞名。两张卡取了同一个角色名时，后者会加序号，同一批角色每次算出来的名字都一样。

下载时靠 `index.json` 把云端的角色名对回本机原来的 png 文件名。换了台机器、本机没有这张卡时，会按角色名新建一个文件 —— 酒馆会把它当成一张名字正确的新卡，不会丢内容。

## 覆盖行为

下载时本机同名文件会被云端版本**直接覆盖，不留副本**。酒馆本身允许存在多张同名角色卡，所以这里不额外往 `backups/` 里堆一份原文件。

用户人设与 API 配置是例外。它们存在 `settings.json` 与 `secrets.json` 里，下载时**逐键合并**：只有你勾的那个人设、那一档配置会被云端版本覆盖，本机独有的留着，这两个文件里其余的内容不动。

不确定会动到哪些文件就先点「预览变更」，它只比对不写入。

## 自动上传

「自动上传」区域可以开启定时自动备份：

- **启用** —— 默认关闭
- **聊天变化后检查** —— 默认开启。发消息、改消息、切聊天等事件触发后 5 秒检查一次
- **间隔** —— 默认 6 小时。距上次自动上传不足这个间隔就跳过

自动执行只做**上传**，永远不会自动下载覆盖你的本机文件。这几个选项改完立刻生效并自动保存，不用再点保存配置。

## 坚果云与其他服务

坚果云需要使用 WebDAV 的「应用授权密码」，不要直接使用账号登录密码。

1. 注册并登录坚果云账号。
2. 在坚果云账号设置中找到「安全选项」或「第三方应用管理」相关页面。
3. 添加应用并生成应用授权密码。
4. 在本扩展里手动填写坚果云提供的 WebDAV 地址、账号和应用授权密码。

坚果云官方教程：[如何开启 WebDAV 并获取应用授权密码](https://help.jianguoyun.com/?p=2064)

InfiniCLOUD、NAS、Nextcloud、ownCloud、Cloudreve 等服务只要提供标准 WebDAV 地址通常都能用。目录遍历只使用 `Depth: 1` 逐层递归，不依赖 `Depth: infinity`，因此坚果云这类支持不完整的服务也能正常工作。

## 数据与安全

- **全部配置（含 WebDAV 密码）保存在** `SillyTavern/data/<用户>/.sillytavern-cloud-backup/config.json`。这个文件在酒馆的用户数据目录里，不在插件目录里，更新插件不会丢配置。
- 密码通过 `/config/load` 读取时**只返回"存没存"，不返回明文**。
- 本机扫描缓存在 `.sillytavern-cloud-backup/scan-cache.json`，只是加速用的哈希缓存，删掉不影响正确性。
- **API 密钥只在你勾了「API 配置」之后才会离开本机**，而且是明文写进网盘上 `API配置/` 里对应的那份 json。只有被勾中的那几个配置档引用到的密钥会被带上，`secrets.json` 里其余的密钥不会被读取，也不会整份上传。不勾这一类，密钥不出本机。
- 本插件不上传任何数据到除你自己填写的 WebDAV 地址之外的地方。

### 后端接口

全部是 `POST /api/plugins/sillytavern-cloud-backup/<action>`：

| 路由 | 用途 |
| --- | --- |
| `status` | 后端是否存活、是否已存密码、上次备份时间、预设与美化各目录的文件清单、每个角色的聊天条数、人设与 API 配置档的列表 |
| `config/load` / `config/save` | 读写配置。读取时密码只返回 `hasPassword` |
| `test` | 连接测试：传一个测试文件再删掉 |
| `backup/plan` | 预览，只比对不执行 |
| `backup/upload` / `backup/download` | 执行备份 |
| `cloud/list` / `cloud/download` / `cloud/delete` | 云端文件管理 |
| `chats/list` | 某个角色的聊天文件明细。范围弹窗展开一张角色卡时才请求 |
| `cards/embedded-worlds` | 哪些世界书已内嵌在角色卡里，前端据此把它们从列表里隐藏 |

连接信息与范围都从 `config.json` 读，前端不随请求携带地址与密码。随请求带上的只有 `characterNames`（`{ avatar 文件名: 角色名 }`），用来把云端文件存成看得懂的名字 —— png 里的角色叫什么只有酒馆前端知道。

「哪些世界书已内嵌」曾经也由前端算好带上，现在改成后端自己解析 png：酒馆开了 `performance.lazyLoadCharacters` 后，前端拿到的角色数据里 `data.character_book` 被整个丢掉，怎么判都是"没内嵌"。

## 常见问题

### 面板显示「后端未加载」怎么办？

按顺序检查：

1. **重启过酒馆吗？** 服务端插件只在启动时加载一次，装完不重启一定是这个提示。
2. `config.yaml` 里 `enableServerPlugins` 是不是 `true`。Docker 用户要确认改的是**映射出来的** `config/config.yaml`，容器内根目录那个是符号链接。
3. `SillyTavern/plugins/sillytavern-cloud-backup/` 下有没有 `package.json` 和 `server/index.js`。
4. **Docker 用户**：容器有没有把宿主机目录映射到 `/home/node/app/plugins`？没映射的话插件放在宿主机上酒馆也看不见。见 [Docker / NAS / VPS 安装](#docker--nas--vps-安装)。
5. 看酒馆启动日志里有没有 `Initializing plugin from ...sillytavern-cloud-backup`，以及紧随其后的报错。

### 为什么需要服务端插件？能只装前端吗？

不能。很多 WebDAV 服务不允许浏览器网页直接跨域访问 —— 坚果云的 `OPTIONS` 预检请求会返回 401 且不带任何 `Access-Control-Allow-*` 响应头，浏览器直连必然被拦。

SillyTavern 自带的 `enableCorsProxy` 也不适用：它的中间件会对 `PUT` 请求体做 `JSON.stringify`，原始文件字节会被破坏，无法用来上传文件。

### 备份会不会把我的聊天弄丢？

上传只往云端推，不删本机任何文件。下载会用云端版本覆盖本机同名文件，**不留副本** —— 担心的话先点「预览变更」看清楚会动哪些文件，它不写入任何数据。

### 备份会不会把我的 API 密钥传上去？

只有你在「范围」里勾了 **API 配置** 才会。它只带上被勾中的那几个配置档引用到的密钥，在网盘上的 `api-profiles.json` 里是明文。不勾这一类，密钥不会离开本机。

### 下载后聊天没变化？

打开「管理聊天文件」看一眼，下载下来的对话应该已经在列表里了 —— 这个列表是现读磁盘的，不需要刷新页面。

### 世界书菜单里是空的 / 少了几本？

被角色卡内嵌的世界书不会单独列出来，它们跟着角色卡一起备份。菜单底部会写「另有 N 本已内嵌在角色卡里」。如果你所有的世界书都是从角色卡带进来的，这个列表空着是正常的。

### 上传后云端还留着我删掉的角色？

这是刻意的：上传只做"推上去"，绝不删云端文件。要清理就在「云端文件」区域勾选后点「删除选中」。

### 备份失败怎么办？

先点「测试连接」。测试失败通常是 WebDAV 地址、用户名、授权密码或远端目录权限有问题。坚果云用户请确认使用的是应用授权密码而不是登录密码。
